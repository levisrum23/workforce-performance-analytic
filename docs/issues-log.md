# Issues Log (Data Preparation)

Documented decisions made while preparing the operator performance dataset.  
These notes serve as the audit trail for “tell me about a time you found a data inconsistency.”

| #   | Issue                                                 | Magnitude                          | Decision & Rationale                                                                                                                                                                                                                                         |
| --- | ----------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Missing PQS records                                   | ~10% of rows                       | **Excluded**, not imputed. Missing values coincided with planned maintenance / downtime windows. Imputing an average would have masked equipment-related signals and artificially inflated performance scores. Flagged in tooltip as “maintenance downtime.” |
| 2   | Department name inconsistency                         | 6 spelling / abbreviation variants | Standardized to 3 canonical names via SQL `CASE` (Fiberline - Digester, Fiberline - Bleaching, Paper Machine, Power Plant, Recovery Boiler). Prevented fragmentation of department-level analysis.                                                           |
| 3   | Duplicate operators after mid-year shift reassignment | 14 records                         | Deduplicated; retained the later entry and recalculated tenure. Kept a single row per Operator ID so the scatter plot and KPI counts remained accurate.                                                                                                      |
| 4   | Stale DLP scores (> 2 years old)                      | ~11% of operators                  | Created a “stale score” dimension. These operators were excluded from competency-based-pay recommendations until reassessment. Prevented promotion decisions based on outdated evidence.                                                                     |
| 5   | Extreme PQS outliers                                  | 3 values                           | Cross-validated against maintenance logs; confirmed as sensor / instrumentation errors rather than genuine operator performance. Values removed.                                                                                                             |
| 6   | Mixed grain (annual DLP vs monthly PQS)               | Structural                         | Solved in Tableau with a FIXED LOD expression so that monthly records did not inflate averages when filters changed. Guaranteed correct quadrant placement.                                                                                                  |
| 7   | Operators with split tenures across departments       | Small number                       | Tenure recalculated from original hire date rather than time-in-current-department. Avoided understating experience for operators who had rotated.                                                                                                           |

**Outcome**  
All seven issues were resolved before the final quadrant model was built. The published sample (`data/sample/raw_data.csv`) is the cleaned, anonymized result of this process and is intentionally free of the original messiness so that the portfolio remains reproducible and non-confidential.
